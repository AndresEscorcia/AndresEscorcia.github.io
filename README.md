# Portfolio — Harrison Andres Escorcia Palacio

Portfolio estático preparado para publicar en **GitHub Pages**.

## Estructura

- `index.html` — página principal.
- `styles.css` — diseño responsive.
- `script.js` — menú móvil y año automático.
- `projects/` — casos de proyecto.
- `assets/` — reservado para foto, favicon, CV público y evidencias.
- `PRIVACIDAD.md` — qué documentos conviene/no conviene publicar.
- `CONTENIDO.md` — checklist de información y futuras mejoras.

## Publicación en GitHub Pages

1. Crea un repositorio, por ejemplo `portfolio` o `<usuario>.github.io`.
2. Copia el contenido de esta carpeta al repositorio.
3. En GitHub entra a **Settings → Pages**.
4. Selecciona **Deploy from a branch**, rama `main`, carpeta `/ (root)`.
5. Espera el despliegue y configura un dominio personalizado si lo deseas.

## Antes de publicar

- Reemplaza `TU_USUARIO` por tu usuario real de GitHub y LinkedIn.
- Añade una foto profesional únicamente si deseas utilizarla.
- Añade enlaces reales a repositorios/demo cuando existan.
- No publiques la HDV completa ni certificados con número de identificación visible.


## Datos incorporados desde Computrabajo

La versión actual amplía la línea de tiempo profesional y el stack con información adicional del perfil de Computrabajo. Cuando ese perfil solo registra un cargo y fechas, el portfolio no inventa funciones: deja el caso preparado para que se complete con evidencia.


## Criterio de redacción

El contenido público del portfolio debe mantener tercera persona o redacción profesional neutra. La primera persona queda reservada, si se decide utilizarla, para textos explícitamente personales y no para describir experiencia o responsabilidades profesionales.
